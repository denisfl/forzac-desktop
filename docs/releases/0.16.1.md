Forzac 0.16.1: a thank-you instead of a plea.

The last line of the help used to say "Forzac is free. Support it", which sounded like a collection box by the door.
Now it reads: "There could be an ad here. There isn't, and there won't be, so Forzac runs on your thanks 😀". The
thanks open the support section of [forzac.app](https://forzac.app/#support); the same line is in About on the Mac.

## Downloads

| | |
|---|---|
| Mac, Apple Silicon, macOS 14+ | `Forzac-macos-arm64.dmg`. If you have 0.11 or later, the library offers the update itself. A first download is signed ad hoc, not notarised: allow it once in System Settings → Privacy & Security → Open Anyway ([step by step](https://github.com/denisfl/forzac-desktop/blob/main/docs/macos-first-open.md)) |
| Arch, Omarchy | The AUR packages are waiting for AUR registration to reopen. Meanwhile the same PKGBUILD from this repository: `git clone --depth 1 https://github.com/denisfl/forzac-desktop && cd forzac-desktop/packaging/aur/forzac-bin && makepkg -si` |
| Debian 13, Raspberry Pi OS 13 (arm64) | `forzac-linux-arm64.deb`: `sudo apt install ./forzac-linux-arm64.deb` |
| Other Linux with GTK 4.14+ | `forzac-linux-x86_64.tar.gz`, `forzac-linux-aarch64.tar.gz`: unpack and run `forzac-0.16.1-linux-<arch>/bin/forzac` |

Check a download with `shasum -a 256 -c --ignore-missing SHA256SUMS`.

## What was checked, and what was not

- Core tests and the Mac app built locally, the help and About not looked at by hand; both shells built and linted by CI.
- Not tried by hand: the help's link on the Pi 5.

There could be an ad here. There isn't, and there won't be, so Forzac runs on [your thanks](https://forzac.app/#support) 😀
